# Coursemos Downloader — Chrome 확장

웹페이지의 영상을 찾아 **MP4** 또는 **M4A**로 저장한다.
로컬 앱이나 ffmpeg 설치가 필요 없고, 확장 하나로 끝난다.

| 형식 | 어떻게 받나 |
|---|---|
| **HLS** (`.m3u8`) | MPEG-TS 조각을 받아 MP4 컨테이너로 리먹스 |
| **DASH** (`.mpd`) | 영상·소리 트랙을 각각 받아 하나의 MP4로 합침 |
| **직접 파일** (`.mp4` `.webm` `.m4v` `.mov` …) | 브라우저 다운로드로 그대로 넘김 |

## 재인코딩을 하지 않는다

조각 안의 H.264 영상과 AAC 오디오 비트스트림을 **그대로 꺼내 MP4 컨테이너에
다시 담기만 한다**(리먹스). 압축을 풀거나 다시 하지 않으므로

- 화질·음질이 원본과 동일하다
- 14분 강의 기준 전체 처리가 **1초 남짓**이다
- 무거운 인코더(ffmpeg.wasm 등)를 번들할 필요가 없다 — 리먹서는 84KB다

오디오만 받을 때 MP3가 아니라 M4A인 것도 같은 이유다. 스트림 안의 오디오가
이미 AAC라서, M4A로 담으면 인코딩이 0회지만 MP3로 바꾸려면 재인코딩이 필요하다.

## 설치 (개발자 모드)

1. Chrome에서 `chrome://extensions` 열기
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 이 `extension/` 폴더 선택

Chrome 116 이상이 필요하다 (offscreen 문서 API).

## 사용법

1. 강의 영상 재생 페이지를 연다
2. 확장 아이콘을 누른다 — **팝업이 열리는 순간 페이지를 직접 훑어 영상을 찾는다**
3. 형식(MP4 / M4A)과 파일 이름을 정하고 **다운로드**

영상이 로드돼 있으면 툴바 아이콘에 개수 배지가 뜨고 플레이어 우하단에
**이 영상 저장** 버튼도 나타나지만, 둘 다 없어도 아이콘만 누르면 된다.

그래도 못 찾으면 팝업의 **↻** 로 다시 검색하거나 **m3u8 주소 직접 입력**을 쓴다.

### 썸네일

팝업을 열면 페이지의 `<video>`에서 **그 순간의 프레임**을 캔버스로 캡처해
카드에 띄운다. 세그먼트를 따로 받지 않으므로 비용이 거의 없다(160px JPEG, 약 2KB).

아직 프레임이 없으면 video.js 포스터 → `og:image` 순으로 대체하고, 셋 다 없으면
재생 아이콘을 그대로 둔다. 캡처는 팝업이 물어볼 때만 하고, 주기적인 감지
보고에서는 건너뛴다.

영상이 여러 개 잡혀도 **첫 번째에만** 붙인다. 플레이어가 실제로 틀고 있는 건
하나뿐이라, 나머지에 같은 그림을 붙이면 다른 차시를 잘못 보여주게 된다.

### 감지가 팝업에서 이뤄지는 이유

캐시된 감지 결과에만 의존하면 두 상황에서 빈 화면이 뜬다.

- **서비스 워커는 30초쯤 놀면 종료된다.** 메모리에 담아둔 감지 결과가 사라져서,
  영상을 좀 보다가 아이콘을 누르면 아무것도 없다
- **확장 설치 이전부터 열려 있던 탭에는 콘텐츠 스크립트가 주입되지 않는다.**
  페이지를 새로고침해야만 감지가 시작된다

그래서 팝업은 열릴 때마다 `activeTab` 권한으로 탐지 스크립트를 (중복 실행 가드와
함께) 주입하고 모든 프레임에 직접 결과를 물어본다. 영상이 iframe 안에 있어도
가장 많이 찾은 프레임의 결과를 쓴다. 세션 스토리지 캐시와 설치 시 자동 주입은
배지를 유지하기 위한 이중 안전장치다.

## 어떤 사이트에서 되나

**HLS(`.m3u8`)로 영상을 트는 사이트면 대체로 된다.** 특정 사이트에 맞춘 코드가
아니라 네 단계로 훑기 때문이다.

| 단계 | 무엇을 보나 | 잡아내는 경우 |
|---|---|---|
| 1 | 모든 태그의 속성값 | video.js `data-setup` 류 (INU LMS) |
| 2 | 인라인 스크립트 본문 | 설정 객체에 URL을 박아둔 플레이어 |
| 3 | **Resource Timing 기록** | **hls.js처럼 JS로만 가져가고 DOM에 안 남기는 플레이어** |
| 4 | DASH 매니페스트 · 직접 파일 | `.mpd`, 그리고 `<video src>`로 그냥 트는 영상 |
| 5 | 세그먼트 경로 추론 | 플레이리스트 요청은 놓치고 `.ts`만 보이는 경우 |

`.mp4`는 경로 끝에 있을 때만 파일로 본다. 그래야 `.../abc.mp4/index.m3u8` 같은
HLS 경로나 `chunk-0-00003.mp4` 같은 조각을 파일로 오인하지 않는다.

3번이 일반화의 핵심이다. 브라우저가 페이지의 모든 요청 URL을 기록해두므로,
팝업을 열 때 그걸 읽으면 **소급해서** 찾을 수 있고 추가 권한도 필요 없다.
영상을 한 번 재생한 뒤 아이콘을 누르면 대부분 잡힌다.

마스터 플레이리스트(다중 화질)면 대역폭이 가장 높은 것을 자동으로 고른다.

### 검증된 사이트

| 사이트 | 형태 | 결과 |
|---|---|---|
| 인천대학교 LMS | HLS 미디어 플레이리스트 직결, 720p | 14:29 → 23.6 MB, 0.8초 |
| test-streams.mux.dev | HLS 마스터 5화질, 1080p 선택 | 10:34 → 465 MB, 11.3초 |
| dash.akamaized.net | DASH 10화질 + 별도 소리 트랙 | 10:34 → 600 MB, 16.3초 |

DASH 결과물은 ffprobe로 트랙 두 개(h264 1920x1080 + aac 48kHz)와 재생 시간
일치를 확인했고, 전체 디코드 오류 0건, 소리도 실제로 들어 있다(평균 -31.6 dB).

### 상시 감지 켜기

기본적으로는 **아이콘을 누른 그 순간, 그 탭에서만** 동작한다(`activeTab`).
자주 쓰는 사이트라면 팝업에서 **이 사이트 자동 감지 켜기**를 누르면 그 사이트에
한해 권한을 받아, 페이지를 열자마자 배지와 인페이지 버튼이 뜨도록 등록한다.
Chrome 설정에서 권한을 회수하면 등록도 자동으로 해제된다.

### 안 되는 것

- **유튜브.** Chrome 웹스토어 개발자 정책이 유튜브 다운로드 확장을 금지한다.
  유튜브 이용약관에도 어긋나고, 기술적으로도 HLS가 아닌 서명된 DASH라
  이 구조로는 처리할 수 없다
- **DRM(Widevine 등)이 걸린 스트림.** 넷플릭스 같은 상용 서비스 전반
- **암호화된 HLS.** `#EXT-X-KEY`가 있으면 명시적으로 거부한다
- **조각 오프셋이 파일 절대 위치 기준인 DASH.** 조각을 재배치할 수 없어 명시적으로
  거부한다. 요즘 DASH는 대부분 `default-base-is-moof`를 써서 문제되지 않는다
- **여러 Period로 나뉜 DASH.** 첫 Period만 받는다

## 권한

| 권한 | 이유 |
|---|---|
| `downloads` | 완성된 파일을 다운로드 폴더에 저장 |
| `offscreen` | 팝업이 닫혀도 다운로드가 이어지도록 백그라운드 문서 사용 |
| `activeTab`, `scripting` | 사용자가 ↻를 누른 그 탭에만 탐지 스크립트 주입 |
| `storage` | 설정 보관 |
| `host_permissions: lms.inu.ac.kr` | 강의 페이지에서 스트림 주소 탐지 |
| `optional_host_permissions: *://*/*` | **미리 받지 않는다.** 사용자가 "이 사이트 자동 감지 켜기"를 누른 그 사이트에 대해서만 그때 요청한다 |

영상 CDN은 `Access-Control-Allow-Origin: *`을 주므로 **CDN에 대한 별도 권한이
필요 없다**. CORS를 막는 CDN을 만나면 `optional_host_permissions`로 그때
사용자에게 물어본다.

## 구조

```
manifest.json                  MV3 매니페스트
src/common/extract.js          URL 추출·분류, 제목, HLS 플레이리스트 파싱 (공유)
src/common/dash.js             DASH 매니페스트 파서
src/common/fmp4.js             영상·소리 트랙을 하나의 MP4로 합치기
src/content/detect.js          페이지 감지 + 인페이지 저장 버튼(단독 다운로드)
src/content/inpage.css
src/background/service-worker.js  상태 보관, 배지, 작업 조율
src/offscreen/offscreen.js     세그먼트 다운로드 + 리먹스 + Blob 생성
src/popup/                     팝업 UI (6개 상태)
vendor/mux-mp4.min.js          mux.js 리먹서 (Apache-2.0)
tools/make-icons.mjs           아이콘 생성기 (Figma C01 안을 코드로 재현)
tools/preview.html             확장 로드 없이 팝업 상태 확인
```

### 왜 offscreen 문서인가

- **서비스 워커**는 언제든 종료되고 `URL.createObjectURL`을 쓸 수 없다
- **팝업**은 닫히는 순간 스크립트가 죽어 다운로드가 끊긴다

그래서 실제 작업은 offscreen 문서에서 하고, 서비스 워커는 조율만,
팝업은 상태를 읽어 그리기만 한다.

## 개발

```bash
npm test          # 단위 테스트 (43개)
npm run icons     # 아이콘 재생성
npm run preview   # 팝업 미리보기 서버 → /tools/preview.html
```

### 아이콘

파란 마름모 + 흰 C. 도형 좌표는 Figma의 `Icon Drafts — C mark › C01 Faithful`
프레임 값을 `tools/make-icons.mjs`에 그대로 옮긴 것이다. 디자인을 고치면
두 곳을 함께 맞춰야 한다. 생성된 128px는 Figma 렌더와 PSNR 43dB로 일치한다.

16px만 따로 보정한다. C의 흰 획은 128px 기준 9.9단위인데 그대로 줄이면
16px에서 1.2px가 되어 획이 사라진다. 16px에서만 고리를 키우고 굵혀 2.2px를
확보했다. 원본 비율 그대로 보려면 `FAITHFUL=1 npm run icons`.

| 크기 | C 획 두께 |
|---|---|
| 128 | 9.86px |
| 48 | 3.70px |
| 32 | 2.46px |
| 16 | 2.20px (보정) — 보정 없으면 1.23px |

실제 스트림으로 전 구간을 돌려보는 통합 테스트:

```bash
npm run e2e -- "<m3u8-url>" mp4 out.mp4
```

offscreen 작업자 코드를 그대로 실행하므로 플레이리스트 파싱, 동시 다운로드,
순서 보장, 리먹스가 전부 검증된다.

## 한계

- **DRM/암호화 스트림은 저장할 수 없다.** `#EXT-X-KEY`가 있으면 명시적으로 거부한다
- HLS·DASH는 완성 파일을 메모리에 Blob으로 들고 있다가 저장한다. 1080p 10분이
  약 600 MB였다. 그래서 DASH 화질은 기본 1080p까지만 고른다
  (`offscreen.js`의 `MAX_HEIGHT`). 직접 파일은 브라우저 다운로드로 넘기므로
  이 제약이 없다
- 동시에 한 개씩만 다운로드한다

재배포·공유는 저작권 침해에 해당할 수 있으며, 소속 기관의 학칙·이용약관을 따를 것.
